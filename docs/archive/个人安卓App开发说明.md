# 个人安卓 App 开发说明

> 历史三入口精简方案。以下范围和参数描述当时原型；当前完整产品以 [功能 V2](../个人生活管理App_完整功能与数据模型设计_V2.0.md)、[工程指南](../安卓本地版工程结构与开发指南.md) 和 [UI V3](../iOS风格安卓UI与UX动效设计_V3.md) 为准。

版本：设计规格 v1.0 · 2026-10-24

## 1. 这份方案适用什么情况

已经明确的条件：自己使用、安卓手机、日常生活场景、数据可保存在本地。本机开发环境已完成构建、模拟器安装和点击验证，详情见 [环境报告](../安卓开发环境配置与验证.md)。

**用户已确认第一版用途为“日常待办＋随手记录”。名称暂用“日常”，视觉方向采用清爽绿色。** 记账、习惯打卡和物品管理暂不加入第一版；如果后续决定增加，应先单独定义数据和页面。

本次交付是开发说明、UI 规范和交互示意；工作区现有的 `android-environment-check` 是环境验收程序，尚未实现本文的业务功能。

## 2. 第一版解决什么问题

打开手机后，可以快速知道今天有哪些事、记下一条生活信息，并在以后找回来。断网时仍可新增、查看、修改和搜索；换手机时可通过自己导出的文件迁移。

建议先实现下面的完整闭环，再增加其他功能。

| 功能 | 第一版行为 | 完成标准 |
| --- | --- | --- |
| 待办 | 新建、编辑、完成、取消完成；可选一个计划日期 | 保存后关掉 App 再打开仍存在 |
| 今日清单 | 显示逾期、今日、未设日期的未完成事项 | 日期规则明确，跨午夜或回到前台时更新 |
| 全部待办 | 查看未来事项和所有未完成事项 | 不会因为未到计划日期而找不到事项 |
| 已完成 | 查看完成历史、恢复为未完成 | 操作后首页和历史同时更新 |
| 随手记录 | 文本标题、正文、置顶、编辑 | 支持中文、换行、长内容 |
| 搜索 | 待办在“全部”搜索；记录按标题和正文搜索 | 输入、清空和无结果状态完整 |
| 回收站 | 删除进入回收站；可以恢复或手动永久删除 | 误删后可以找回；永久删除需确认 |
| 数据备份 | 导出 JSON、选择文件导入、显示导入预览 | 取消、坏文件、重复导入都不会破坏现有数据 |
| 设置 | 跟随系统／浅色／深色、备份入口、版本信息 | 重启后保留外观选择 |

第一版范围外：账号、多人协作、云同步、AI、广告、复杂统计、富文本、图片附件、定位、闹钟和重复任务。它们属于后续候选功能。尤其是“计划日期”仅用于清单分组，第一版不会发送提醒通知。

## 3. 页面和主要操作

底部固定三个主要入口：**今日、记录、设置**。搜索和编辑是进入后的页面，不额外占一个底部入口。

```text
今日
  ├─ 今天 / 全部 / 已完成
  ├─ 待办详情与编辑
  └─ 新建待办
记录
  ├─ 搜索、置顶与最近修改列表
  ├─ 记录详情
  └─ 新建／编辑记录
设置
  ├─ 外观
  ├─ 备份与恢复
  ├─ 回收站
  └─ 关于与版本
```

三个高频流程：

1. 记一件事：今日 → “添加待办” → 输入标题 → 保存 → 清单立即出现。
2. 记一条信息：记录 → “写一条” → 输入内容 → 保存 → 最近修改列表出现。
3. 换手机：旧手机导出备份 → 自行转移文件 → 新手机安装 App → 导入预览 → 确认导入。

## 4. 功能规则，开发前就约定清楚

### 4.1 待办

- 标题必填，去掉首尾空白后 1～120 个 Unicode 码点；备注最多 5,000 个码点。前端提示与导入验证使用同一套规则，不截断用户文字。
- 计划日期可为空。为空表示“未设日期”，不是默认今天；只表示日期，不记录提醒时间。
- 今天页展示：逾期未完成 → 今天未完成 → 未设日期未完成。未来事项只在“全部”显示。
- “全部”默认只显示未完成：有日期的按日期升序，同一天按创建时间升序，最后显示未设日期；用 UUID 作最终稳定排序键。
- “已完成”按完成时间降序，不按原计划日期排序。
- 点击复选框只切换完成状态；点击文字区域进入编辑。两处触摸区域分开，避免误操作。
- 完成时写入 `completedAt`；取消完成将它清空。不额外维护一个容易不同步的 `isCompleted` 字段。
- 删除设置 `deletedAt`，从正常列表消失；恢复清空它并保留原完成状态。回收站第一版不自动清空。
- 日期按手机当前本地日期判断；保存 ISO 日期 `YYYY-MM-DD`，不能用某个 UTC 时间戳冒充“哪一天”。切换时区不改变用户选定的日历日期。

### 4.2 随手记录

- 标题最多 120 个码点，正文最多 20,000 个码点；二者至少有一个去空白后非空。
- 无标题时列表显示正文首个非空行的前 30 个码点，后续用省略号；详情仍完整展示。不要把自动摘要回写成用户标题。
- 置顶项在前，组内按修改时间降序；标题、正文、置顶变化更新 `updatedAt`。
- 搜索采用本地文字匹配，待办匹配标题和备注，记录匹配标题和正文。第一版不做拼音、分词、联网搜索。
- 输入约 250ms 后更新结果；清空立即还原。SQL 参数绑定，并转义 `%`、`_` 和转义符，让它们按普通文本搜索。
- 删除、回收站、恢复规则与待办一致。永久删除前显示具体名称，避免笼统的“确定吗”。

### 4.3 保存和草稿

- 正式内容使用明确的“保存”按钮。只有数据库事务提交成功，才能显示“已保存”并返回列表。
- 保存期间按钮禁用，避免连续点击生成重复内容；失败时留在编辑页、保留输入，并提供重试。
- 编辑草稿与正式内容分开保存：输入停止约 500ms 后写入本地草稿表；界面只在写入成功后显示“草稿已保存在本机”。
- 重新进入同一编辑页发现草稿时，提供“继续草稿／放弃草稿”。提交成功后在同一 Room 事务中保存正式条目并删除草稿。
- 返回时如有未提交内容，提供“保留草稿并返回／继续编辑／放弃修改”。保留草稿必须等待写入成功再离开；失败时不假装成功。
- 极端情况下，在最后一次输入尚未落盘的 500ms 内进程被强制结束，最后这部分输入可能丢失。草稿不作为正式备份内容。

## 5. 技术选型和理由

| 部分 | 建议 | 用在什么地方 |
| --- | --- | --- |
| 开发语言 | Kotlin | 安卓原生功能与业务逻辑 |
| 界面 | Jetpack Compose + Material 3 | 页面、表单、列表、主题、弹窗 |
| 页面状态 | ViewModel + StateFlow | 加载、保存、错误、筛选、当前编辑状态 |
| 异步处理 | Kotlin Coroutines / Flow | 数据读写、搜索、导入导出 |
| 内容数据库 | Room | 待办、记录、草稿、回收站状态 |
| 少量偏好 | Preferences DataStore | 外观、上次成功导出时间等 |
| 导航 | Jetpack Navigation 3，建正式工程时核对兼容版本 | 管理主入口和详情／编辑返回栈 |
| 文件导入导出 | Android 系统文件选择器（SAF） | 让用户决定备份文件的位置 |
| 依赖组织 | 单模块、手动依赖注入 | 第一版用一个容器创建数据库和 Repository |

Room 适合结构化的本地内容，DataStore 适合少量设置，不应把所有笔记塞进设置文件。[Room 官方说明](https://developer.android.com/training/data-storage/room)、[DataStore 官方说明](https://developer.android.com/topic/libraries/architecture/datastore)。

采用页面状态单向流动：界面提交操作，ViewModel 处理并更新状态，Compose 观察状态后刷新；使用 `collectAsStateWithLifecycle()`。导航和系统文件选择器由 UI 层处理，不把 Activity 或界面控制器放进 ViewModel。新建 Compose 工程的导航方向参考 [Android 架构建议](https://developer.android.com/topic/architecture/recommendations)。

### 5.1 与现有环境如何衔接

现有验收基线：JDK 21、Gradle 8.13、AGP 8.12.2、Kotlin 2.2.10、Compose BOM 2025.08.00、compileSdk／targetSdk 36、JVM target 17。这些是已验证组合，不表示它们是当前最新版本。

正式项目建议放在独立目录 `daily-life-android`，保留环境验收工程。采用版本目录 `libs.versions.toml` 集中管理依赖。Room／KSP、DataStore、Lifecycle、Navigation、序列化是新增依赖，**还没有在当前验收工程中构建验证**。启动正式项目时先解析依赖并完成空壳构建，再锁定兼容版本；若需升级工具链，分开验证，避免一次更换全部组件。

最低安卓版本暂按 Android 8 / API 26，需以自己的真实手机版本复核；目标版本先沿用已验收的 API 36。此前没有连接真实手机，因此不能把模拟器结果当成真机兼容结论。

### 5.2 建议目录

```text
daily-life-android/
  app/src/main/java/<正式包名>/
    app/                Application、依赖容器、导航
    data/local/         Room 数据库、实体、DAO、迁移
    data/repository/    待办、记录、设置的数据入口
    data/backup/        文件格式、导入校验、导出
    feature/today/      今日、全部、已完成
    feature/task/       待办编辑
    feature/notes/      记录列表与编辑
    feature/settings/   设置、备份、回收站
    ui/theme/           颜色、字体、形状
    ui/components/      空状态、条目、错误提示
  app/schemas/          Room 导出 schema
  gradle/libs.versions.toml
```

第一版不必拆成许多 Gradle 模块；重复业务逻辑出现后再提取 use case。列表使用 `LazyColumn` 并提供稳定 ID，避免内容增多后一次构建全部行。[Compose 列表说明](https://developer.android.com/develop/ui/compose/lists#item-keys)。

### 5.3 开发时具体怎样开始

1. 重新打开 Android Studio，让已经配置的环境变量生效。
2. 新建 **Empty Activity / Jetpack Compose** 项目，使用 Kotlin；项目位置设为 `D:\desktop\myapp\daily-life-android`，最低版本暂选 API 26。名称和包名在正式安装前确定。
3. SDK 位置使用 `E:\AndroidSDK`，Gradle JDK 使用 `E:\Android\jbr`。项目 JDK 与系统默认 `java` 命令的版本可能不同，以 Gradle 实际 JVM 为准。
4. 先保留工具链的已验证组合，核对新增依赖兼容性，完成同步和空壳构建；若 Android Studio 模板生成了其他版本，先检查差异再决定是否采用。
5. 建立主题和三个入口，再接 Room；每做完一个完整流程就安装到模拟器验证。真实手机连接后补充键盘、系统返回、文件选择器和覆盖安装验证。
6. 调试使用独立测试数据，日常真实数据先备份再做升级测试。正式版签名和数据迁移在首次长期使用前完成。

如果使用终端，在正式项目已经创建后，可以这样构建：

```powershell
. D:\desktop\myapp\tools\Enter-AndroidEnvironment.ps1
Set-Location D:\desktop\myapp\daily-life-android
.\gradlew.bat assembleDebug --console=plain
```

安装包会位于正式项目的 `app\build\outputs\apk\debug\app-debug.apk`。现有 `Invoke-AndroidBuild.ps1` 和 `Verify-AndroidApp.ps1` 针对环境验收工程，正式产品应另配自己的构建与验收入口。

## 6. 数据结构

时间戳统一保存 UTC 毫秒，展示时转本地时区；“计划日期”单独存 ISO 日期字符串。ID 使用 UUID，备份和导入沿用原 ID。

| 表 | 关键字段 | 约束／索引 |
| --- | --- | --- |
| Task | id、title、description、plannedDate?、createdAt、updatedAt、completedAt?、deletedAt? | 主键 id；索引 deletedAt、completedAt、plannedDate；标题非空 |
| Note | id、title、body、isPinned、createdAt、updatedAt、deletedAt? | 主键 id；索引 deletedAt、isPinned、updatedAt |
| EditorDraft | draftKey、kind、targetId?、payloadJson、updatedAt | 主键 draftKey；新建每种内容保留一个草稿，编辑用条目 ID 定位 |

`kind` 为 `task` 或 `note`；`payloadJson` 使用独立版本字段和与正式编辑器相同的验证模型。Room 数据库版本和备份文件版本是两个概念，分别管理。

DataStore 保存 `themeMode`、`lastSuccessfulExportAt`。备份时间只代表成功导出文件，不代表上传成功或文件永远有效；导入文件不能伪造本机上次导出时间。

数据库升级必须提供迁移并保留历史数据，提交 schema 文件；正式版禁止用破坏性迁移清库兜底。

## 7. 本地存储和备份

数据库放在 App 私有目录。日常读写无需联网，也无需申请广泛存储权限。文件导入导出通过系统选择器，让用户主动选一个文件或保存位置。[Android 文件访问说明](https://developer.android.com/training/data-storage/shared/documents-files)。

卸载可能清除私有数据，设备损坏也会造成数据丢失，所以第一版必须把导出和恢复做完整。建议以手动备份为基线，在设置中明确最近一次成功导出时间。系统自动备份不作为唯一恢复途径；若承诺纯本地保存，需配置并实测系统备份与设备迁移规则，明确厂商差异。

### 7.1 第一版文件格式

使用 UTF-8 JSON，文件名如 `daily-life-backup-20261023-230000.json`，MIME 为 `application/json`。不含附件，暂不需要 ZIP。

```json
{
  "format": "daily-life-backup",
  "schemaVersion": 1,
  "exportedAt": "2026-10-23T15:00:00Z",
  "appVersion": "0.1.0",
  "tasks": [],
  "notes": []
}
```

条目内容使用上表字段；导出包含正式条目的完成／置顶和删除状态，因此回收站可恢复内容也会随文件迁移；不包含草稿、缓存、日志、设备标识、签名文件。界面需说明“备份包含回收站内容”。

### 7.2 导出规则

1. 从同一个一致性数据库快照读取待办与记录，在后台序列化，避免边写边导出导致不一致。
2. 系统选择器取消时回到原页，不记录成功。
3. 写完并成功关闭输出流后显示成功、更新时间；写入中断则提示可能存在不完整文件，允许重新导出。
4. 使用有界处理：第一版导出／导入共同限制总条目不超过 10,000 条、JSON UTF-8 大小不超过 20 MiB。先校验再写文件；超限给出明确提示，不生成声称完整却截断的备份。容量扩大作为后续版本单独实现。
5. 文件未加密，导出前提示一次“备份包含你的文字内容，请保存在可信位置”。不把导出文件写入开发日志。

### 7.3 导入规则

1. 用户选文件后，限制读取大小；验证格式标识、版本、数组、条目类型、UUID、字段长度、日期和时间戳。未知较新版本提示不支持，不猜测结构。
2. 同一文件内重复 ID、无效字段、超限内容视为文件错误，整次拒绝；现有数据库完全不变。
3. 显示预览：“待导入待办 X 条，记录 Y 条；已有 ID Z 条将跳过；其中回收站 W 条”。第一版采取**只加入新 ID，已有 ID 保留本机版本**的合并方式。
4. 清楚说明该模式不会恢复同 ID 的旧版本，也不用于跨设备冲突同步。预览取消时不写入。
5. 用户确认后在单一事务中导入，期间阻止编辑；如数据库在预览后发生变化，重新统计并让用户确认，不能悄悄换一套计数。
6. 任意写入失败回滚；重复导入同一文件不会增加重复条目。导入成功后列表从数据库重新读取。

只保留一套导入策略，先降低误覆盖风险。以后若要“以备份完全替换本机”，必须另做完整预览、自动保留旧数据和失败恢复方案。

## 8. 开发顺序和每一步的交付物

| 顺序 | 工作 | 可查看的结果 | 通过后再进入下一步 |
| --- | --- | --- | --- |
| 1 | 确定主要用途、名称、自己手机版本 | 确认后的范围清单 | 首页和数据类型一致 |

| 4 | 记录 + 搜索 + 草稿 | 可以实际记录生活内容 | 长内容、中文、草稿恢复通过 |
| 5 | 回收站 + 备份导入导出 | 可迁移和找回数据 | 重复／损坏文件不会破坏数据 |
| 6 | 暗色、字体、键盘、横屏适配 | 可日常使用的测试版 | UI 规范与状态检查通过 |

可用工作量估计：熟悉 Kotlin／Compose 的开发者，在用途不变且无附件提醒的前提下，约 7～12 个工作日形成可用第一版；初学者需要额外学习时间。这是范围估计，不是已承诺的工期。先完成步骤 2～3，就能尽早在手机上检验交互是否合适。

## 9. 验收标准

### 功能和数据

- 新建待办、修改、完成、恢复；重开 App 后一致；未到日期的事项可从“全部”找到。
- 昨天／今天／明天、无日期、跨午夜、切换时区的分组正确。
- 记录支持中文、表情作为内容、换行、最大长度；保存失败保留输入；连续点击只保存一次。
- 搜索 `%`、`_`、引号时不变成通配搜索或引发 SQL 错误。
- 草稿保存后退出再进可继续；保存正式内容后旧草稿不再弹出。
- 删除可恢复；永久删除确认中显示正确条目；恢复完成事项后回到已完成列表。
- 导出后在干净安装的数据环境中导入，内容、ID、日期、完成／置顶、回收站状态一致。
- 重复导入计数不增加；坏文件、过大文件、版本不支持、取消选择、磁盘写入失败均不破坏现有数据。
- 数据库升级保留旧版数据；覆盖安装保留数据库；卸载前完成有效备份。

### 界面和体验

- 飞行模式可完成核心功能；无网络时不出现无意义的错误横幅。
- 小屏、横屏、字体 200% 和真实手机软键盘下，保存按钮和输入错误仍可触达。
- 浅色／深色文字清晰；状态不只靠颜色；TalkBack 能读出按钮名称和待办完成状态。
- 系统返回先关闭键盘／弹窗，再按当前导航返回；未提交编辑不会被静默丢弃。
- 性能目标：在自己的真机、发布构建中测量，冷启动可交互争取 2 秒内；本地保存与 1,000 条数据搜索的常见操作争取 300ms 内反馈。目标不代表已经实测达到。

自动化优先覆盖日期规则、搜索转义、导入校验／事务／幂等、数据库迁移和保存失败这些高风险逻辑；Compose 仪器测试覆盖新建后重开、完成状态、编辑返回等主要流程。配色、文案等低影响改动主要做预览和人工检查。

## 10. 长期个人使用要保留的东西

正式安装前确定稳定 `applicationId`，使用单独的个人发布签名；签名密钥和密码独立备份，不进版本库，不提交到对话或日志。以后使用同一签名并递增版本号，才能正常覆盖升级。调试签名只适合开发验收。

保留三类资产：代码和 Room schema、正式签名的安全备份、真实数据的可恢复备份。前两类负责后续升级，最后一类负责换机和故障恢复。

UI 规格、组件尺寸、配色及逐页状态见 [UI 设计说明](UI设计说明.md)。
