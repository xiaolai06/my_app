# 个人生活管理 App 安卓本地版技术与存储方案

日期：2026-10-24。当前已确认：安卓、个人使用、数据保存在本机。本方案用于指导正式项目开发；不表示业务功能已经实现。

工程目录、功能对应文件、开发步骤及打包安装见 [安卓本地版工程结构与开发指南](安卓本地版工程结构与开发指南.md)；字段与业务规则见 [完整功能与数据模型设计 V2.0](个人生活管理App_完整功能与数据模型设计_V2.0.md)。

交给 AI 实施时从 [项目指引](../AGENTS.md) 与 [任务交接](ai/开发任务与交接.md) 进入；全部有效资料和历史分类见 [文档索引](README.md)。

## 1 确定采用的方案

**Kotlin + Jetpack Compose + Room/SQLite + DataStore + 应用内部附件目录。**

所有核心功能在断网时可用。当前不建设账号、服务器、云数据库或多设备同步；完整功能设计中的云同步章节仅保留为未来参考。

2026-10-26 用户授权增加可选城市天气：默认关闭，手动查询名称或选择城市坐标后通过 HTTPS 请求 Open-Meteo；不申请 GPS、不上传业务资料。城市/开关仍存 DataStore，可丢弃的天气响应只存 cache，断网保留有明确时间的缓存，过期数据不参与温度推荐。衣橱/穿搭、手账与提醒仍完全本地；`records.presentation` 和 `plan_reminders.deferredUntil` 通过 Room 3→4 加法迁移加入。版本与验证事实见 [本轮交接](ai/开发任务与交接.md#lifestyle-upgrade)。

| 部分 | 选择 | 用途 |
| --- | --- | --- |
| 开发工具 | Android Studio | 沿用本机已验证的安卓环境 |
| 语言 | Kotlin | 业务逻辑与系统功能 |
| 页面 | Jetpack Compose + Material 3 | 五入口、列表、编辑、主题、自定义视觉 |
| 状态 | ViewModel + StateFlow | 加载、筛选、编辑、保存和错误反馈 |
| 异步 | Coroutines / Flow | 数据读写、查询和文件处理 |
| 导航 | Navigation 3 | 页面跳转和返回来源 |
| 数据库 | Room，底层 SQLite | 业务表、关系、查询和事务 |
| 简单设置 | Preferences DataStore | 主题、字号、金额显示等少量偏好 |
| 到时提醒 | AlarmManager + 系统通知 | 按系统能力和权限安排本地提醒 |
| 延迟后台工作 | WorkManager | 可延迟的清理、补齐周期实例等，不负责准点提醒 |
| 备份数据编码 | kotlinx.serialization JSON | 版本化导出、校验与恢复 |
| 文件进出 | 系统文件选择器与分享入口 | 导入附件，选择导出备份位置 |

先采用一个正式 App 工程，按记录、计划、账本、生活工具等目录组织；初期手动依赖注入。复杂财务操作集中到业务服务，不散落在页面内。依赖版本先做兼容构建，再锁定，不将新加依赖视为已验证。

参考：[Android 架构建议](https://developer.android.com/topic/architecture/recommendations)、[Room](https://developer.android.com/training/data-storage/room)、[DataStore](https://developer.android.com/topic/libraries/architecture/datastore)。

## 2 数据分别存在哪里

| 数据 | 存储位置 | 例子和规则 |
| --- | --- | --- |
| 核心业务 | 一个 Room 数据库 | 任务、记录、账目、账户、习惯日志、物品、标签、草稿、引用 |
| 小型设置 | DataStore | 主题、字号、上次成功备份时间；卡片等结构化配置仍放数据库 |
| 附件原件 | 内部 files 目录 | 图片、PDF、录音；使用文件编号命名 |
| 可再生成文件 | cache 目录 | 缩略图、临时预览；清理不影响原件 |
| 完整备份 | 用户选择的应用外位置 | 文档目录、U 盘或导出后复制到电脑；不默认上传 |

应用私有目录中的建议布局：

```text
databases/
  daily_life.db                 Room 管理的业务数据库
files/
  datastore/                    DataStore 管理的设置
  attachments/<文件编号>/       附件原件
cache/
  thumbnails/                   缩略图
  previews/                     临时预览
```

目录实际位置由 Android API 获取，不硬编码某台设备的系统路径。数据库保存附件名称、相对路径、类型、大小、校验值；文件原件不塞进数据库。导入成功后复制到内部目录，不依赖来源应用的临时访问地址。

内部目录不需要申请通用存储读写权限；导入导出使用系统选择器。卸载应用或清除应用数据会清除这些本地内容，完整备份需要独立保存在应用外。[内部文件存储说明](https://developer.android.com/training/data-storage/app-specific)

## 3 数据库怎样组织

- 一个数据库内按业务建表，模块之间引用原编号；不为今天页、专题等入口复制账目或任务。
- 一条记录使用稳定 UUID；金额使用 Long 整数分，时长使用整数秒，日历日期与具体时间点分开保存。
- 财务交易和账户分录一起提交；缴费状态与关联支出一起提交，避免只成功一半。
- 普通删除写入删除时间，默认保留 30 天；恢复沿用原编号。财务依赖和仍被引用的附件先校验。
- 数据表按开发阶段逐步建立；不为尚未实现的云同步提前增加服务或队列。
- 升级版本使用 Room 数据迁移；禁止用清空数据库来解决迁移失败。升级后要验证旧记录、附件与余额仍正确。

详细字段与关系以 [完整功能与数据模型设计 V2.0](个人生活管理App_完整功能与数据模型设计_V2.0.md) 为准。迁移参考 [Room 官方说明](https://developer.android.com/training/data-storage/room/migrating-db-versions)。

## 4 本地保存流程

```text
用户编辑
  → 保存本地草稿
  → 点击正式保存
  → 校验字段与关系
  → 数据库事务提交
  → 页面显示成功并刷新相关入口
```

附件先复制并校验成功，再提交引用。保存失败保留输入；重复点击复用同一次操作，不能重复入账。断网不影响新增、编辑、搜索、记账与打卡。

## 5 备份与换机

首版提供“导出完整备份”和“从备份恢复”，建议连续使用 7 天未成功备份时在应用内提示。提醒只提示用户，不自动选择位置或上传。

| 备份内容 | 说明 |
| --- | --- |
| manifest.json | 格式版本、创建时间、记录数、附件数、校验清单 |
| data.json 或分领域 JSON | 正式数据、原编号、标签、关联、重复规则、历史和未清理回收站 |
| attachments/ | 引用到的附件原件 |
| settings.json | 可迁移的外观等设置；不含设备认证密钥 |

- 从一致的数据快照导出，并按清单校验附件；不要直接复制正在写入的数据库文件当作完整备份。
- 一般数据导出可打包 ZIP；提供口令加密时使用明确的加密包格式，不能把普通 ZIP 标成加密备份。首版至少具备可验证的完整导出与恢复。
- 导出后显示成功时间、条目数量与位置；缺失附件时明确提示不完整。
- 恢复前预览、校验版本与空间；合并按编号去重，有冲突先核对；覆盖前先保存当前数据的回退备份。
- 新手机安装同一应用后选择备份包恢复；不需要登录。导入后重新检查通知权限并安排有效未来提醒。
- 同一应用签名的正常覆盖更新应保留数据；开发和日常使用保持签名连续，升级前备份并验证迁移。

## 6 本地隐私规则

- 当前不集成登录、云同步、远程统计或自动上传组件；链接收藏需要打开原网页时交由用户选择的浏览器。
- 显式配置 Android 系统备份规则，业务数据库、设置与附件不进入系统云备份；设备迁移行为按目标系统和真机核对，换机以用户导出的备份包为准。
- 系统可能自动备份应用数据，不能只因为应用没有服务器就认为不会发生系统云备份。[Android 备份规则](https://developer.android.com/identity/data/autobackup)
- 可提供系统生物识别或设备认证作为应用锁；它控制访问，不等于已经为全部数据库和附件实现独立加密。
- 分享附件使用临时授权，敏感信息和金额按用户设置隐藏；备份包由用户自己保管，可复制一份到电脑以防手机丢失。

## 7 正式开发顺序

1. 创建安卓正式工程与五入口，沿用已验证工具链，验证新增依赖。
2. 接入 Room、DataStore、草稿和回收站，完成保存、重启与恢复。
3. 先打通任务、随记、基础记账，再接附件和搜索。
4. 实现完整备份与恢复，验证覆盖安装、数据库升级与换机恢复。
5. 按完整功能设计扩展日程、预算、习惯和其他生活模块，再验证提醒与跨模块一致性。

基础框架不需要额外服务器资源；实际开发重点是数据可靠保存、财务一致性、附件引用、备份恢复和安卓提醒适配。
