## 后续使用

用 Android Studio 打开以下项目文件夹：

`D:\desktop\myapp\android-environment-check`

在 Android Studio 的设置中搜索 Gradle JDK，验收工程已配置使用本机 JDK。SDK 位置应为 E:\AndroidSDK。

永久环境变量已写入当前 Windows 用户配置；重新打开开发工具使其读取新值。当前已经打开的终端可以直接运行下面的环境脚本，无需等待重新登录。

在项目根目录 D:\desktop\myapp 的 PowerShell 终端中运行：

```powershell
# 让当前终端使用同一套安卓工具
.\tools\Enter-AndroidEnvironment.ps1

# 构建验收安装包
.\tools\Invoke-AndroidBuild.ps1

# 复核环境并保存记录
.\tools\Test-AndroidEnvironment.ps1

# 启动独立模拟器，安装 App，验证点击，保存截图，再关闭模拟器
.\tools\Verify-AndroidApp.ps1
```

安装包输出：`D:\desktop\myapp\android-environment-check\app\build\outputs\apk\debug\app-debug.apk`。

验收日志、截图、环境记录位于 `D:\desktop\myapp\diagnostics`，已从版本控制中排除。本机 SDK/JDK 路径和参数应在换电脑时重新确认。

真实手机调试还需在手机端开启 USB 调试、连接数据线并确认授权。首次安装后可使用 USB 调试持续更新应用。

## 恢复用户环境变量

需要恢复本次变更前的用户环境变量时，在 PowerShell 中运行：

```powershell
.\tools\Restore-AndroidEnvironment.ps1 -BackupDirectory 'D:\desktop\myapp\diagnostics\backups\20261023-225443'
```

恢复脚本保留已安装的 SDK 工具和验证项目，不删除原有软件。恢复后重新打开开发工具，使其读取环境变量。

## 本次保留的边界

现有 Android Studio、ADB、模拟器和 SDK 镜像没有执行整套升级，也没有清空现有缓存或虚拟设备数据。本次目标是建立并验收一套相互兼容的开发基线。

新装的命令行工具会提示 sdkmanager 已被 Android CLI 取代；这是工具弃用提示，旧入口仍可正常查询 SDK。Windows 下的虚拟设备验证使用 avdmanager / emulator / ADB 的兼容入口。
