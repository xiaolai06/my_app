## 2. 整体视觉：克制的玻璃与清楚的内容

### 2.1 看起来是什么样

- 浅色：雾蓝灰背景、静止的淡蓝/薄荷/灰紫色域；分组表面明显透出色域，顶部高光与底部暗边形成厚度。深墨色正文和蓝色主操作保持清楚。
- 深色：深灰蓝背景、低亮度蓝/青/紫色域、浅灰白文字、浅蓝选中态；亮边降低强度，避免白色描边发光。
- 标题大而清楚；一组相关信息放进同一个圆角容器，用细分隔线区分，避免每行都变成悬浮大卡片。
- 按钮、搜索、输入框、复选框、开关、导航、弹层、提示使用同一套着色、边缘和圆角规则。组件有统一材质，但不同信息层级的透明度不同。
- 图标统一为简洁线性图标；导航文字始终可见。颜色只强调当前操作和状态，不给每个模块刷一种鲜艳底色。

Apple 将材质放在层级与可读性中讨论。本产品让内容与内部控件都使用玻璃语言，同时为正文、表单和金额提供稳定底色；实时光学增强集中在操作与导航层。这是独立的安卓设计，不是 Apple 组件运行在 Android 上。[Apple 材质指南](https://developer.apple.com/design/human-interface-guidelines/materials)

### 2.2 三层材质

| 层 | 用在哪里 | 外观 | 绘制成本 |
| --- | --- | --- | --- |
| 内容层 Content | 正文、账目、任务分组、长表单 | 静止背景透色、双边缘、柔和接触阴影；长文/密集金额提高底色遮盖 | 默认普通 Compose 绘制 |
| 控件层 Control | 按钮、筛选、输入框、勾选、开关、内部图标底座 | 透色渐变、倒角亮边、局部选中透镜、按压反馈 | 普通绘制；不逐个实时采样 |
| 浮层 Floating | 底部导航、菜单、日期/时间选择、快速新增与编辑弹层 | 强于内容层的磨砂、较厚边缘、稳定可读底色与层间阴影 | 增强档才引入共享背景采样 |

文字、图标、光标和选择高亮最后清晰绘制，不参与模糊或折射。输入框不是透明洞；账目和长文章下面不放持续运动的色块。两个浮层不重复叠加重模糊。

### 2.3 设计变量

| 项目 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | #E9EFF6 | #111720 |
| 实色回退表面 | #F9FBFF | #202936 |
| 正文 | #192638 | #EDF2FB |
| 次要文字 | #3D4E65 | #C6D1E2 |

| 主色上的文字 | #FFFFFF | #142E55 |

正文最低 4.5:1；有意义的图标、状态边界和焦点最低 3:1。分隔线仅作装饰，不能单独承担状态表达。半透明材质须在真实合成背景上重新测量，固定色计算不代表全部玻璃状态达标。

字号用系统字体与 sp：页标题 32/40、分组标题 17/24、正文 16/24、辅助 14/20、标签 13/18、导航 12/18。斜杠后为行高。中文正文不以 12sp 压缩密度。金额使用等宽数字特性，不引入 SF Pro 或苹果专属字形。

V3.1 材质起始值：浅色表面为白色 62% → #F8FCFF 40%，亮边白色 93%，底缘 #5474A0 15%；深色为 #3D526F 66% → #1D2B40 62%，亮边 #D2E7FF 32%。浮层额外叠加浅色 #F3F9FF 82% / 深色 #1D2C43 94% 的稳定底色；长正文原生档位最低遮盖建议 82%。这些值需随实际合成背景调校。

浏览器预览以 22px 模糊、1.3 饱和度表现磨砂，底栏单独 16px 模糊；这不是 Android 的 22dp 参数，也不是实时折射。Android 初始增强模糊仍从 12dp 试起，先满足一处共享背景和少量实时区域的预算。

## 3. 信息架构与导航

### 3.1 五个固定入口

| 入口 | 用户主要问题 | 内容 |
| --- | --- | --- |
| 今天 | 我现在先处理什么？ | 选定日期、待办、日程、近期生活提醒、最近记录 |
| 记录 | 刚才的想法、资料放哪里？ | 随记、日记、资料、收藏、信息卡、收件箱、资料夹、标签 |
| 计划 | 我怎样安排时间与目标？ | 任务、日历、习惯、专注、目标 |
| 账本 | 钱花在哪里，余额是否清楚？ | 收支、账户、预算、统计、转账、退款、报销、导入导出 |
| 功能箱 | 其他生活事情在哪里管？ | 清单、纪念日、订阅、缴费、物品、借还、专题、计算 |

顶部左侧为产品标识，右侧为全局搜索与“我”。头像进入个人、外观、提醒、隐私、备份、回收站、存储与帮助；不占第六个主入口。首次进入今天，无登录引导。

### 3.2 底栏的具体设计

- 五个等宽区域，顺序固定；图标在上、文字在下，始终显示。正文不会推动底栏上下跳动。
- 原生导航内容区最小 76dp，底部另加系统 navigationBars Insets；大字体允许增高，不锁定总高度。预览的像素留白不作为 Android 系统高度。
- 每项至少 48dp 触摸宽度、68dp 高；图标 23dp，选中图标底板 52×32dp，文字 12sp/18sp。
- 选中态使用主色文字/图标和稳定底板；选中颜色 180ms 原位变化、正文 160ms 淡变。底板只在本项内，不跨栏滑动，不改变入口宽度，不隐藏文字；系统或用户减少动态时即时切换。增强光学材质仍需后端与真机验证。
- 记录、计划、账本的新增位于内容区右下；字号超过 1.3 倍时改为独立底部操作行，由布局为按钮保留空间，不遮挡正文。功能箱只在具体子模块提供新增。五栏中间不塞“+”挤走原入口。
- 不支持整页左右滑动切换五个主入口，避免与安卓返回及列表横向操作冲突。
- 切换入口保留列表位置、筛选、月份；从工具跳到计划里的习惯，返回到原工具入口。主入口之间不叠加无限返回历史。

## 4. 五个主页面的具体设计

### 4.1 今天 TOD-01～02

从上到下：日期 → 按用户顺序显示的天气与实际内容卡片 → 卡片与样式设置。正在进行的专注保留单独继续入口。

移除固定待办/完成摘要和四项快捷新增，有内容才展示日程、任务、账本和待整理卡片。首页支持隐藏和调整卡片顺序；天气未启用时提供城市设置入口。列表底部的卡片与样式用“显示开关＋上移/下移”，读屏用户也能排序。

任务圆形复选框和任务文字是两个独立操作：勾选完成，点击文字编辑/查看。完成提供撤销，不能用轻扫作为唯一完成入口。计划日与截止日同时命中今天只展示一条。逾期单独标注，不和“今天计划”混算。

日程显示起止时间、地点和全天状态；事件结束不自动完成任务。生活提醒展示距到期时间与当前状态；“即将续费”不等于“已付款”。卡片点击原对象，不复制出首页专用数据。

### 4.2 记录 REC-01～13、CRD-01～03

首页：搜索框 → 类型筛选 → 收件箱 → 按时间分组的记录。随记、日记、收藏、资料为内容类型；信息卡从“分类与资料”进入。资料夹和标签放在筛选/整理页面，避免首页塞多层工具栏。

记录卡显示类型、标题、最多 2～3 行摘要、日期、标签；不靠随机彩色便签区分。记录太长时进入详情，不能把全文塞入列表。资料卡显示格式、大小、原件状态；无缩略图时仍有文件名。

随记编辑页：标题选填、正文/附件有效内容至少一项、整理选项折叠。日记先选日期，同日已有日记时打开原文或预览合并。收藏编辑显示网址、标题、备注；断网不妨碍保存备注，也不声称已缓存全文。

信息卡采用“字段名—字段值”成对列表，私密字段默认隐藏；复制是明确按钮并提供反馈。资料缺失时显示“原文件找不到”，给重新选择入口，不能伪装为空白笔记。

收件箱表示未整理，归类后原编号不变。批量选择进入专用操作栏，显示数量、移动/标签/删除；底部导航暂时让位给上下文操作，并可明确退出选择。

### 4.3 计划 PLN-01～10、HAB/FOC/GOL-01～04

顶部分段为“任务／日历／习惯／专注／目标”，放在页面内容里，底部五栏不随之变化。

| 子页 | 页面结构 | 核心行为 |
| --- | --- | --- |
| 任务 | 待办/已完成/全部筛选、分组清单 | 标题优先；子任务展开；分组和完成历史为二级页 |
| 日历 | 月份选择、月/周视图、选中日议程 | 全天与定时分开；跨天有明确结束日期；大字改议程列表 |
| 习惯 | 今日打卡、进度、习惯详情/历史 | 次数型与达标型文案不同；修改打卡不重复累计 |
| 专注 | 关联任务、计时、开始/暂停/继续、结束 | 不做呼吸光圈；后台按真实时间段恢复，不能靠页面计数 |
| 目标 | 目标列表、里程碑、进度来源、历史 | 自动累计与手动记录明确区分；来源删除后提示待核对 |

日期选择采用自定义玻璃面板。月格实际可用宽度至少 348dp 才显示七列（7×48dp + 6×2dp）；不足时改七日日期列表、上一周/下一周。大字号或辅助功能需要时也优先列表，不用默认系统日期面板补位。原生按实际字体和剩余空间计算，不能只按屏幕型号判断。

重复规则统一编辑：频率、间隔、结束条件、月末处理、例外预览。编辑已重复事项先选“仅这一次／这次及以后”；根据 V2.0 的实例规则显示影响范围，不凭 UI 复制任务。

### 4.4 账本 LED-01～15

2026-10-26 用户确认的账本优化覆盖旧六分区：顶部只保留「概况、明细、统计、账户」，移除账本根页全局工具栏、通知、重复账本/日常标题与现金流展示。默认单账本不显示名称；存在多个账本时显示当前范围，避免历史数据被误当成全部。预算不占主导航与概况卡，和报销、分类管理、导入导出、回收站一起收进「记账工具」；返回记住原主标签。

参考 [鲨鱼记账官方商店](https://apps.apple.com/cn/app/id1079718756) 的快速录入和消费趋势、[Cashew 官方指南](https://cashewapp.web.app/faq.html) 的分类与渐进展示，以及 [Money Manager 流水](https://help.realbyteapps.com/hc/en-us/articles/360046150874-Home-tab) 和 [统计指南](https://help.realbyteapps.com/hc/en-us/articles/360045310273-Stats-Tab) 的日期、分类与账户组织。只借鉴信息层级；不复制品牌、代码、截图或图标，不宣称未经核实的奖项。

概况：月份 → 本月支出主数字、收入与收支结余 → 消费分类摘要 → 最近账目。退款、报销到账有实际记录时单列；结余=普通收入−消费支出+实际退款，不等于账户余额。明细按日期分组，显示当日普通收支小计、分类图标、事项、日期与带方向的金额。统计支持支出/收入、分类排行和六个月趋势；点击分类或月份进入匹配明细，清除旧日期范围与无关条件，并明示筛选范围。账户显示银行卡等账户类型、尾号、记账余额与原流水。

记一笔：收支类型 → 金额 → 图标分类 → 日期 → 事项 → 可选账户。备注、商户、凭证等按需展开；转账/退款保留其条件必填项。分类面板为可搜索网格，可新建自定义分类并在保存成功后立即选用，图标为本地原创矢量，按名称匹配。日期使用周一开头的自定义月历，提供月份切换、今天、选中语义和确认/取消；普通日格至少48dp，大字体64dp，窄屏允许横向滑动查看完整一周，文字提示自然换行。取消不改变原日期，选未来日期仍由原财务规则拒绝正式入账。

金额完整显示，超长和大字体使用上下布局；隐藏金额同时遮盖分类金额、占比与趋势。普通收支不选账户也可保存；保存仍走原 ViewModel/Repository，失败保留输入，财务规则和备份格式不因布局重排而改变。

| 页面族 | 具体布局 | 状态与防误操作 |
| --- | --- | --- |
| 账户/分类 | 分组列表 → 详情 → 编辑 | 余额校准标注为校准，不能算普通收入 |
| 转账 | 转出/转入两账户、金额、手续费 | 不同账户；摘要说明实际两侧变化 |
| 退款 | 原支出摘要、已退/可退、退款金额日期 | 超额给字段错误；跨月统计口径明确 |
| 预算/统计 | 月份、预算进度、分类列表、可选柱图 | 有金额表可替代图；超额同时有文字 |
| 报销 | 待提交/已提交/部分回款/完成 | 提交与到账分开；展示每次实际回款 |
| 导入 | 选文件 → 列映射 → 校验/重复核对 → 确认 → 摘要 | 错误行可下载/重选；中断不重复写入 |
| 导出 | 范围 → 格式/位置 → 写入 → 结果 | 权限取消与写入失败不报成功 |

统计图不使用大面积霓虹玻璃。金额在数据层以整数分存储，格式化仅发生在 UI；界面无真实支付、扣款或银行绑定入口。

## 6. 组件规范与安卓对应

“Glass UI 组件库”指本产品拟封装的组件层，**不是已经装好的苹果安卓库**。Material 3 提供输入、语义、焦点、弹层和可访问行为；自有主题与表面绘制统一外观。Backdrop 只作为局部背景模糊/透镜效果的可选后端，不负责页面、导航或数据。

| 拟封装组件 | 尺寸与状态 | Compose 实现基础 |
| --- | --- | --- |
| GlassSurface / Group | 24dp 圆角；内容、控件、浮层三档 | Surface / Box + Brush + 独立描边层 |
| GlassButton / IconButton | 主要 50～52dp 高；图标触摸 48dp；可用/禁用/按压/忙碌 | Button / IconButton + InteractionSource |
| GlassTextField / Search | 单行至少 52dp；17dp 圆角；标签不只靠 placeholder；玻璃倒角与稳定文字底色 | BasicTextField + decorationBox 或定制 TextField container，文字不模糊 |
| GlassCheck / Switch | 视觉 23dp 或轨道 49×29dp，触摸至少 48dp | Checkbox / Switch 或 toggleable + 正确角色 |
| GlassSegment / Filter | 高至少 48dp；选中态局部淡变；长文字可换行 | SingleChoiceSegmentedButtonRow / FilterChip，必要时包换行容器 |
| TaskRow / RecordCard | 行高至少 72dp；编辑和完成两块区域 | LazyColumn，稳定 item key；正文 wrapContentHeight |
| GlassBottomBar | 五等宽、80dp + 系统 Insets；标注选中 | NavigationBar / NavigationBarItem 主题定制 |
| GlassSheet | 顶圆角 28dp；内容可滚；长编辑全屏 | ModalBottomSheet / 全屏编辑目的地 |
| GlassDialog | 最少动作、明确对象与影响 | AlertDialog；永久删除明确确认 |
| GlassSnackbar | 最多一个撤销动作；不遮住底栏 | SnackbarHost，使用辅助功能建议时长 |
| GlassDatePicker / MonthPicker | 月格/七日列表、月份网格、今天下划线、日程点、确定/取消 | Dialog/Popup + 自有日历布局与日期状态；Java Time；不直接使用默认日期面板外观 |
| GlassTimePicker | 24 小时，小时/分钟双列、48dp 项、确定/取消 | LazyColumn + selectable 与清晰选中语义；保留 1 分钟精度 |
| GlassSelect / Menu | 触发器至少 52dp、选项至少 50dp；当前项有勾选 | Popup + 自有表面/选项；selectableGroup、焦点、键盘与可访问语义 |
| Amount / Attachment / Status | 完整金额、原件状态、错误文字；不只用颜色 | Text + semantics，系统文件与照片选择器 |

用户交互控件应显式留够触摸区域，避免只靠框架扩大命中范围而互相重叠。Android 建议最小 48dp 目标；自定义外观也须保留同样可访问语义。[Android 组件无障碍](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)

### 6.1 内部控件的统一材质

组件不再只把外层卡片做成玻璃。输入框、搜索框、下拉触发器、图标底座、勾选圆点、开关滑块、分段选中块、日期格与时间选项，均使用同源的透明渐变、倒角高光和接触阴影。避免每一层各用一套蓝色、阴影和圆角。

| 状态 | 外观反馈 | 额外行为 |
| --- | --- | --- |
| 默认 | 弱透色、清晰轮廓；正文保持墨色/浅灰白 | 触摸范围覆盖完整控件 |
| 选中 | 局部玻璃透镜变亮，底缘略深；蓝色文字/图标 | 菜单有勾选；分段/日期有选中语义 |
| 按下 | 绘制层轻缩放，亮边短响应 | 不改变布局与邻项位置 |
| 聚焦 | 独立清晰焦点轮廓 | 不以玻璃反光代替焦点提示 |
| 错误 | 字段附近显示具体错误文字与语义 | 保留输入；移动到首个错误 |
| 禁用/忙碌 | 降低强调、文字仍能读，阻止重复操作 | 对外暴露禁用/进度状态 |

长文章、表单错误、金额等阅读重点不能直接叠在高对比运动背景上。用户切换“清晰实色”后取消采样与透色背景，保留形状、层级、选中勾和状态颜色。

### 6.2 定制下拉、日期与时间

**下拉选择**：触发器显示当前值与向下箭头。打开一层锚定磨砂菜单，自动避开边缘；当前项是局部玻璃高亮＋勾选。单选点按立即回填并关闭；点击外部或返回取消。方向键移动焦点，Enter/空格选择，Esc 关闭并回到触发器。较长选项列表可滚动，不能让弹层溢出窗口。

**日期选择**：面板顶部显示字段名、待确认日期与关闭；中部为月份/年份按钮和前后切换；下部显示月格或七日列表，底部为“取消／确定”。点月份标题打开 12 月网格，可前后切年份；按实际日历计算月长、星期和闰年。“今天”用下划线与读屏文字表示；有日程用圆点与读屏文字表示；已选用透镜底板，三种状态可同时存在。相邻月日期可直接选中。选择仅改变待确认值，取消不改变表单；确定才提交。

**时间选择**：24 小时，小时 00～23、分钟 00～59 双列；每项至少 48dp，当前项有玻璃高亮和选中语义，上方显示完整 HH:mm。初次打开滚到当前值附近，改变小时不重置分钟滚动。取消保留原时间，确定才回填；不因“好看”限制为 5 分钟粒度。原生使用 LazyColumn 管理绘制，读屏按“9时／35分”播报。

**浮层与返回顺序**：一次只激活一个选择器。其余内容不能被误触或获得焦点，Tab/读屏焦点留在当前层；关闭选择器恢复原字段。返回先关最上层选择器，再处理编辑器和未保存确认。键盘、遮罩与选择器不能争抢同一次返回。

### 6.3 安卓实现安排

在 ui/components 中规划 GlassSurface、GlassSelect、GlassMenu、GlassDatePicker、GlassMonthPicker、GlassTimePicker、GlassSegment、GlassSwitch、GlassBottomBar；具体模块路径以工程指南为准。业务页面只传标签、值、选项、错误、启用状态和回调，不各写一套材质。

1. 先以 Compose Foundation/Material3 的布局、输入、Popup/Dialog、焦点与 semantics 构建完整可用行为，外观由本项目 Brush、轮廓和阴影绘制。
2. 日期用 LocalDate；开始时刻用 LocalTime；年月浏览状态与已提交日期、待确认日期分别保存。日期切换不自动开启提醒，选择器关闭也不写业务数据库。
3. 选项、日期、时间都有稳定编号与选中语义；触摸、键盘与 TalkBack 使用同一个状态源。列表重组不能使焦点突然回到页面顶部。
4. 基础档所有控件都可用且有玻璃语言；API31+ 可选共享背景模糊，API33+ 折射仅作为后续候选。不要把前景文字一起调用 blur，也不要给每一个日期格创建实时采样层。
5. 减少动态、清晰实色、字体增大是组件参数，而非业务页面里的例外分支。先验证基础档，再按第 8 节决定 OPPO 真机是否开启增强。

本轮只实现了浏览器交互预览与设计变量。上述 Kotlin 组件、日期状态持久化和原生语义仍须在正式工程实施；未新增 UI 库或改动安卓工具链。

## 7. UX 动效：反馈动作，而不抢注意力

以下数值是本产品设计起点，原生需要根据真机帧时间和系统动画设置调校。没有无限追光、循环浮动、页面旋转或跨栏胶囊。

| 交互 | 运动设计 | 时长与曲线 | 减少动态 |
| --- | --- | --- | --- |
| 按下按钮 | 控件绘制层缩到 0.975，不改变布局占位；亮边轻降 | 按下 80ms，松开 220ms；(.2,.8,.2,1) | 仅颜色变化 |
| 主入口切换 | 当前项颜色/玻璃高光原位淡变；正文最多 3dp 上移淡入 | 高光 220ms，正文 240ms；(.2,.8,.2,1) | 原位切换 |
| 页面详情 | 新页面轻淡入；返回由 Navigation/系统手势驱动 | 建议 220ms；手势中不硬套固定时长 | 保留状态关系，取消额外位移 |
| 弹层展开 | 遮罩淡入，表面从下方 36dp 内进入 | 360ms；(.2,.8,.2,1) | 即时显示 |
| 弹层关闭 | 表面下移 25dp 内并淡出；原生手势取消回原位 | 180ms；(.4,0,1,1) | 即时关闭 |
| 下拉菜单 | 以锚定位置轻移 4dp、0.98→1，选中反馈局限在本项 | 进入 180ms；预览关闭即时 | 即时显示/关闭 |
| 日期/时间面板 | 从下方 20dp、0.985→1；日期选中不抖动、不跨格滑块 | 进入 300ms，局部状态 220ms；预览关闭即时 | 即时结果 |
| 开关 | 滑块平移，内高光和轨道颜色同步更新 | 滑块 280ms；(.2,.8,.2,1)，轨道 220ms | 即时切换 |
| 勾选任务 | 先显示勾选，再收起；邻行连续移动，撤销恢复原位置 | 勾选 160ms，收起/重排 180～240ms | 状态即时更新 |
| 习惯打卡 | 勾选与次数变化；可选轻系统触感 | 160ms，不撒彩带 | 即时变化 |
| 筛选/搜索 | 筛选选中高光；搜索只更新结果，不重建输入 | 高光 220ms，筛选内容 240ms；搜索即时局部更新 | 即时结果 |
| 表单保存 | 点击锁定重复提交；耗时可见“正在保存”；成功后关闭 | 与真实提交同步，不为动画延迟保存 | 同样完整反馈 |
| 验证失败 | 错误出现在字段附近，焦点到首个错误 | 120ms 淡入，不晃动输入框 | 即时错误 |
| 进度/预算 | 用户改变数据后，条形平滑更新 | 240ms ease-out；首次加载不从 0 炫动 | 即时数值 |
| 专注计时 | 数字按秒变化，暂停状态明确 | 无翻页/呼吸循环；不逐帧重绘全页 | 同样可用 |
| 删除与撤销 | 删除到回收站后提示；撤销时恢复原对象 | 重排 180～240ms；提示时长适配读屏 | 即时布局、保留撤销 |
| 主题切换 | 同步替换主题色，避免整屏缩放闪白 | 最多 220ms 色彩过渡；不重播页面入场 | 即时更换 |

预览已经有按压、局部玻璃选中、编辑弹层进入/退出、菜单与选择器进入、开关滑块、页面进入、进度变化与减少动态模式。菜单和选择器的预览退出即时；原生可按受支持组件实现连续退出。原生组件、列表重排、交互式返回、触感及键盘联动均属于待实施项。

原生可用 animateColorAsState/animateFloatAsState 管理简单状态，用 AnimatedVisibility 管理显隐，LazyColumn 的稳定 key 配合 animateItem 管理插入/重排；实际数据提交由状态层负责，动画结束回调不能充当保存成功信号。[Compose 动画指南](https://developer.android.com/develop/ui/compose/animation/quick-guide)、[Compose 列表动画](https://developer.android.com/develop/ui/compose/lists#item-animations)

### 7.1 返回、编辑和手势优先级

键盘正在输入 → 系统先收键盘；有菜单/日期选择 → 先关闭；有短弹层 → 先关闭；有未提交编辑 → 保留草稿或确认放弃；最后才离开详情/根页面。实际优先级须让系统 IME 与组件处理，不写一个覆盖所有返回事件的根级拦截器。

五个主入口不被当成五级历史；从今天进入任务、或从专题进入记录，返回都回到来源位置。不要给退出 App 再加一次“确定退出”。

Navigation Compose 与 Material3 的受支持组件可接入预测返回；应使用项目兼容版本并验证手势取消、键盘与弹层同时出现的情况。根 Activity 无条件拦截会影响系统返回动画。[Android 预测返回说明](https://developer.android.com/develop/ui/compose/system/predictive-back-setup)

### 7.2 保存与失败

编辑状态区分未修改、已修改、保存中、成功、失败。失败留在表单中，保留正文与附件引用，提供重试；成功以数据库/文件实际提交为准。重复点按只能产生一次对象。

短表单可用底部弹层；长记录、复杂账目、备份核对用全屏目的地。键盘弹出不让整个弹层被推到屏幕外。需要放弃修改时先给“继续编辑／放弃修改”，不能在轻扫中静默丢失正文。

## 8. 安卓适配与性能策略

### 8.1 屏幕、字体和系统区域

| 条件 | 适配 |
| --- | --- |
| 窄窗口 320～359dp | 16dp 边距；单列；筛选换行；金额可增高；底栏仍五等宽 |
| 常规手机 360～599dp | 20dp 边距；分组单列；工具两列；主操作易点到 |
| 宽窗口 ≥600dp | 可用 NavigationRail，列表/详情双栏；文字阅读宽度约 640dp 上限 |
| 字体 1.3～2.0 倍 | 内容与按钮增高、辅助信息换行；任务不固定高度；底栏允许增高并保留标签；超过 1.3 倍时新增改独立底部操作行，正文与按钮不重叠 |
| 横屏或键盘占用高 | 长编辑转全屏；表单滚动到焦点；常驻导航在编辑目的地隐藏 |
| 手势/三键导航 | 分别读取系统 Insets，不能写死“底部 24dp” |
| 刘海/挖孔 | 内容与触摸避开 cutout；不把示意状态栏画进正式 App |

启用 edge-to-edge 后，分别处理顶部状态栏、底部导航、IME；Scaffold 内边距与组件 Insets 不能重复叠加。聚焦字段用可滚动布局配合 bringIntoView；IME 动画跟随系统，不手写固定键盘高度。[Android Insets 与 IME](https://developer.android.com/develop/ui/compose/system/insets-ui)

玻璃弹层背后可显示内容，但点按必须被遮罩阻断；打开后焦点进入弹层，关闭后回到来源。TalkBack 能区分“完成任务”和“编辑任务”，状态改变适量播报，不每秒播报专注计时。

### 8.2 三档材质后端

| 档位 | 适用能力 | 实现 | 使用策略 |
| --- | --- | --- | --- |
| 基础 | minSdk 26 起 | 渐变、着色、细亮边、低阴影 | 全组件一致风格；原生默认起点 |
| 模糊增强 | API 31+ 候选 | 共享背景源 + 背景副本 RenderEffect | 先只在底栏或当前弹层使用 |
| 轻折射增强 | API 33+ 候选 | 背景采样 + RuntimeShader / Backdrop lens | 小位移；关闭色散；真机通过后可选 |

普通 Modifier.blur 不能自动把后方内容捕获成玻璃背景。背景源、玻璃背景和前景文字分开绘制，采样空间与裁剪对齐，避免递归采到玻璃自身。

Backdrop 文档说明其效果基于 RenderEffect，Android 12+ 才生效；涉及 RuntimeShader 的部分需要 Android 13+。建议按文档顺序组织颜色处理、模糊、透镜。它是增强效果候选，**本项目尚未安装、集成或验证该库**，依赖版本和许可在引入时核对。[Backdrop 官方效果文档](https://kyant.gitbook.io/backdrop/api/backdrop-effects)

所有组件统一风格，不等于每个任务行、开关和输入框都创建一套背景纹理。页面最多优先保留一个共享背景捕获源；底栏与当前浮层先以最多两处实时区域作为预算起点，而不是框架保证。

### 8.3 OPPO 真机调优顺序

1. 读取真实 Android/ColorOS、屏幕尺寸与当前刷新率；不根据机型名推断性能。
2. 用基础材质构建发布配置，验证字体、键盘、手势导航、三键导航与任务操作。
3. 加入底栏背景模糊，滚动长列表、展开键盘和快速切页，比较与基础档的帧时间。
4. 再加轻折射，建议初始采样位移不超过 2dp；有闪烁、掉帧、可读性下降即回退。
5. 深色、低亮度、系统减少动画、省电和温升条件复测；用户始终能选择“清晰实色”。

首版用用户设置和能力判断选择档位；自动温控/省电降档需要独立状态设计与实测，当前不声称已实现。避免运行中频繁跳档闪烁；仅在稳定窗口或下次进入界面时切换。

### 8.4 性能验收目标

- 以设备当前刷新率为准：60Hz 一帧约 16.7ms，120Hz 约 8.3ms；这只是预算换算，不是已达成的实测帧率。
- 发布配置与固定数据集记录 P50/P95/P99 帧时间、慢帧比例、内存、长时间使用温升，记录测试路径和实际模式。
- 先优化布局与重组，再调整模糊；列表稳定 key，避免滚动时重建画刷、Shader、纹理和整页数据。
- 背景静止不持续刷新光学效果；专注计时只更新计时文本；切到后台停止装饰动画。
- 通过条件以基础档为参照：交互无可见卡顿、失败可恢复、无持续增长的内存，增强档劣化时回退；具体硬阈值在真机基线建立后固定。

### 12.3 原生五入口实施

用户本轮要求将新增与编辑操作移到底部。原生记录页采用右下「写记录」悬浮入口，内容类型、模板和草稿在底部菜单；记录、计划与账本在字号超过 1.3 倍时使用独立底部新增操作行，正文为其保留空间。长文全屏编辑，格式、预览、图片、文件、归类、保存集中在底部工具栏，真实 IME/系统导航区域参与布局。

类型筛选最低 48dp、横向滚动；选中使用稳定的色彩/边缘和语义，不再用占位点或额外勾号挤压文字。五主入口固定等宽，局部选中，不跨栏移动；根页无重复大标题。浅深主题、增强磨砂底色和减少动态通过 DataStore 保存；减少动态时底部浮层改无位移动画对话层。日期选择遵守 348dp/字体阈值，窄屏为七日列表，并保留直接输入。

0.3.0 首页直接聚合原对象，支持卡片排序/隐藏和日期选择；账本按概览、明细、统计、账户、预算、管理组织，报销/导入/账户流水/现金流为次级页。功能箱按生活、物品、效率、计算分组，各子页进入实际编辑和详情；计算结果带入待确认表单。列表、筛选、区间和返回来源按业务模块保留，编辑与详情隐藏底栏，实际 Insets 由系统读取。

当前玻璃是 Compose 原生渐变、透色、边缘与阴影；没有实时模糊或折射。输入、开关等部分基础控件仍由 Material 3 提供交互，尚不能宣称全套光学增强组件库完成。图片/PDF 使用原生预览。详细功能和实际测试以 [工程说明](../daily-life-android/README.md)、[任务与交接](ai/开发任务与交接.md) 为准。
