# 给 AI 开发者的执行说明

更新：2026-10-24。用途：让具备项目文件读写能力的 AI 在同一套规则下继续安卓开发。本文说明如何执行，不替代功能、UI 和数据模型原文。

## 1 开始前确认三件事

1. **本次做什么**：以用户本次授权为边界。整理文档不启动业务工程；“实现 DEV-004”只交付该任务及必要依赖；“连续完成核心阶段”则持续完成该范围，不每做一个文件就请求确认。
2. **现在有什么**：查看 [任务与交接](开发任务与交接.md) 与实际文件。目录图是计划，网页内存预览是示例，环境项目是工具链验证，三者不能当作业务完成证据。
3. **依据是什么**：先读 [AGENTS.md](../../AGENTS.md)，再按 [文档索引](../README.md) 查相关领域。默认使用最新有效规格，历史文件和外部项目只提供参考。

遇到普通实现细节可按现有约定推进，并在交接中记录。影响数据安全、正式包身份或产品方向且无法从已有要求确定时，先完成不受影响的部分，再集中说明待决定的问题。设备未连接时可以完成代码和模拟器验证，将真机项标为未验证，不把整项工作停在等待手机。

## 3 单个功能的交付流程

| 步骤 | 执行动作 | 结果 |
| --- | --- | --- |
| 确认输入 | 列出必填、默认、条件必填、选填和边界，核对已有数据 | 明确的保存命令与表单状态 |
| 核对存储 | 复用已有表，定义关系、约束、索引和迁移 | Entity/DAO/schema；避免重复事实 |
| 实现规则 | 事务内校验、幂等、冲突、财务或数量计算 | Repository，必要 UseCase/Service |
| 实现交互 | 列表、详情、编辑、返回来源、键盘与无障碍 | 真实数据驱动的 UI；失败保留输入 |
| 接公共能力 | 按适用范围接草稿、附件、标签、搜索、提醒、回收站 | 从其他入口查看同一个对象 |
| 接迁移与备份 | 新字段加入导出恢复、旧版本转换和引用检查 | 旧数据不丢，新对象可恢复 |
| 验证 | 执行相关规则测试、构建和可完成的设备流程 | 记录实际结果与未验证项 |
| 交接 | 更新原任务行和交接记录，指出下一步 | 下一个 AI 无需猜测进度 |

未实现的入口可以在调试演示中明确标“未实现”；正式使用界面不显示假保存、假支付或看似可用的空功能。

## 4 需要特别防止的问题

- **范围遗漏**：先做任务和随记是开发顺序，不代表账本、生活工具等从完整范围删除。
- **财务分叉**：页面、账单导入、缴费和维修不各自改余额；统一走交易与分录事务。
- **提交后重复执行**：通知排程失败不重做已成功保存的账目；导入重试复用批次和行结果。
- **文件与数据库脱节**：复制、校验、引用提交和中断回收分别处理；删除原件查所有引用。
- **升级清库**：不以删除数据库、卸载正式版或破坏式迁移绕过失败；先用测试库复现并修复。
- **预览冒充成品**：Web 示例和内存状态不是 Room 保存；背景透明不代表已经实时折射。
- **新依赖失控**：版本锁定前核对工具链；不同时引入两套背景采样后端。
- **验证结论扩大**：构建通过、模拟器通过、真机通过分别记录；设计参数不是测量结果。

## 5 发给 AI 的任务描述

下面的文本可复制使用；方括号是需要替换的内容。项目指引放在工作区内，普通聊天工具需要同时提供相应文件，只有文件名无法让它读取本机目录。

### 开始正式工程

```text
请读取根目录 AGENTS.md、docs/README.md 和 docs/ai/开发任务与交接.md。
本次授权开始正式安卓业务工程，完成 DEV-001。
在 daily-life-android 新建 Kotlin/Compose 单 app 模块，按工程指南配置和验证基础依赖。
沿用当前五入口完整个人版与本地存储方向，不修改环境验收项目的用途。
执行可完成的构建验证，记录实际版本、产物和未验证项，更新任务与交接。
不要把其余功能标为完成，也不要在本次范围外展开全部业务模块。
```

### 实现指定功能或一段连续任务

```text
请先读取 AGENTS.md、任务与交接，以及 V2/V3 中与本次功能有关的章节。
本次授权范围：[DEV 编号或连续阶段]，目标：[具体可操作的结果]。
请完成真实本地保存、状态刷新、输入校验及适用的草稿/搜索/回收站/备份接入。
按现有单 app 模块结构实现；检查已有改动，不覆盖无关内容。
持续完成范围内的实现和验证，更新原任务状态与证据。
结束时说明改动、实际验证、剩余限制和下一步。
```

### 修复问题

```text
请按 AGENTS.md 检查并修复：[问题描述]。
复现步骤：[进入页面 → 操作 → 实际结果]；期望结果：[期望]。
先确认影响数据和相关规则，再作必要修改，不重写无关模块。
涉及金额、数据库、附件或备份时补充能覆盖该故障的验证。
记录问题原因、修复结果、实际执行的检查和未验证项，并更新交接。
```

## 6 验证与结果记录

| 改动 | 最小相关验证 |
| --- | --- |
| 文档、链接和设计索引 | `tools/Test-ProjectDocs.ps1`，人工核对对应要求 |
| 新依赖、构建配置 | 正式工程依赖解析、`assembleDebug`；必要时 lint |
| 纯金额、日期、周期逻辑 | 本机规则测试，边界与幂等场景 |
| Room、财务、恢复 | 设备端约束/事务/迁移/恢复测试，核对真实结果 |
| 页面和交互 | 相关 Compose 流程；键盘、返回、浅深主题和字体 |
| 通知、文件、正式更新 | 模拟器能测的部分先测；目标手机另列验证 |

命令的运行目录、前提和 APK 路径见 [工程指南第 9 章](../安卓本地版工程结构与开发指南.md#build)。范围外或尚无工程可运行的检查标“不适用/未执行”，不能填“通过”。

交接记录沿用下面的简短格式，不复制整份功能说明：

```text
日期 / 任务：
完成：实际实现的行为与主要文件。
验证：运行目录、命令或手工路径、结果和必要证据。
限制：未验证项、失败原因、数据兼容说明；没有则写无新增限制。
下一步：明确的任务编号和剩余问题。
```

已执行但失败的验证保留失败事实和修复情况。截图、日志、真实个人数据分开处理；交接摘要不含秘密字段、完整账单或签名密码。
