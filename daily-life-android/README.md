# 日常 · 原生个人生活管理

这是正式业务工程，独立于环境验收程序。0.3.0-dev 已接入“今天、记录、计划、账本、功能箱”五入口的本地业务页面；头像进入设置。Kotlin/Compose 原生界面，Room/内部文件保存业务，DataStore 保存外观与首页偏好，无服务器与账号。

## 当前可用

- 随记、日记、图片/文件、链接收藏、字段信息卡。预置九个显示类型，可新增、改名；底层仍是 note / diary / file / bookmark，信息卡是 note/card。
- 底部悬浮「写记录」，底部类型菜单、草稿入口；全屏编辑，格式、图片、文件、附件复用、归类和保存都在底部。
- 中文 Markdown 编辑与原生渲染：标题、粗体/斜体、引用、列表/勾选、代码、表格、http/https 链接。HTML 只作文本，不执行脚本；不加载远程图片，图片以本地附件呈现。
- Room 真实保存、450 ms 防抖暂存草稿、稍后写、继续草稿；修改草稿不会提前改变正式记录。保存失败保留草稿，版本变化会阻止覆盖。
- 标题选填，列表从正文或附件名派生预览，不回写标题；仅标题不能保存。标题最多 120 字、正文 50,000 字，超限保留输入并提示。
- 单层资料夹、多标签、标签改名/合并/删除、分类标准化去重；待整理状态独立。长按多选，批量归类、归档、删除、恢复。
- 自定义日期选择器；窄屏或大字体改为七日列表，可直接输入年月日。日记日历入口、补写、往年同日筛选、有效日记每天唯一；恢复冲突明确拒绝。
- 文件流式导入、SHA-256、应用内部原件、跨记录/草稿引用；图片 20 MB、其他单份 100 MB、每条最多 50 份。取消草稿/删除记录时检查所有引用后清理。
- 图片应用内缩放预览、PDF 分页预览；其他格式交由系统支持应用打开。图片/PDF 可导出原件。
- 收藏默认查重，允许明确另存，保留网址参数；离线保存自己的标题和说明，非网页全文离线。
- 信息卡字段支持文字/数字/日期/链接/电话、私密标记与排序。私密字段默认遮挡，不参与搜索、Markdown 导出和文字分享。模板不保存字段值与附件。
- 本地搜索、类型/资料夹/多标签/日期/状态筛选、置顶与排序、复制、Markdown 导出、系统文字分享、回收站。
- 系统分享的文字/文件/图片先进入草稿，检查后手动保存；同结构显示类型可以更换。
- 浅深主题、减少动态、增强磨砂底色。采用 Compose 原生渐变/高光/边缘/阴影；尚未集成实时背景模糊或液态折射。

## 安装后怎么用

1. 将本目录构建出的 app/build/outputs/apk/debug/app-debug.apk 传到安卓手机安装；这是独立的开发测试包。
2. 进入「记录」，点右下「写记录」选择内容类型。正文支持 Markdown，底部可切换预览、添加图片/文件和归类；点「保存记录」才成为正式记录。
3. 点「稍后写」保留草稿，下次从「写记录」菜单继续。长按记录可以多选归类、归档或移入回收站；资料夹、标签和类型在「管理分类」中维护。
4. 从头像设置分别导出记录、计划、账本、功能箱的 ZIP 备份；工具首页也有功能箱备份。Markdown 和 CSV 不包含附件原件，ZIP 才包含；卸载之前先备份。

## 今天、账本与功能箱（0.3.0）

五个根页不再重复显示模块一级大标题。顶部保留搜索与头像，底部固定五等宽导航；选中背景局限图标区域。普通点击有原生反馈，主入口正文 160ms 淡变、选中色 180ms；系统或用户减少动态时即时更新。字号超过 1.3 倍时，记录、计划与账本的新增按钮改为独立底部操作行，正文为其保留空间。深浅主题统一蓝灰色，表单/长文提高可读底色；目前仍是静态玻璃渐变、亮边和阴影，没有实时背景模糊或液态折射。

### 今天

- 选择日期，查看原任务、日程、习惯、活动专注、近期缴费/订阅/纪念日/待归还、月度账本、最近记录和待整理；没有复制业务对象或虚构统计。
- 首页直接完成原任务；事项点入原详情，返回保留来源。选择历史日期后预算使用所选月份，打开账本也进入该月份。
- 快捷新增随记、任务、日程、支出。首页卡片排序/隐藏、快捷顺序、近期天数、称呼保存到 DataStore；隐藏卡片不删除业务。
- 搜索记录、计划、账目与工具，默认排除归档/回收站，私密信息卡字段和默认私密物品序列号不参与；金额隐藏同步到账本、工具只读预览、首页与全局搜索。

账本布局参考 [Cashew](https://github.com/jameskokoska/Cashew) 的快速记账与分类组织，以及 [Actual 的账户说明](https://actualbudget.org/docs/accounts/) 和 [分类说明](https://actualbudget.org/docs/budgeting/categories/)。只研究交互和信息层级，没有复制其代码、图标或素材；本项目的数据规则按 V2 执行。

### 新增备份与迁移

Room 加法迁移 1→2→3，保留三份 schema；3 增加 14 张财务表和 9 张工具表，未清库。打开正式旧库前进行 WAL 检查点并在 noBackupFilesDir/pre-upgrade-v1 或 pre-upgrade-v2 留内部副本。

账本 ZIP 为 daily-life-ledger/version1/schema3；工具 ZIP 为 daily-life-tools/version1。均先校验固定字段、UUID、关系、版本、文件路径/大小/哈希，再预览并事务追加；已有编号保留本机版本。账本上限为 10000 笔交易，工具上限为 5000 主项；各自所有表合计上限 50000 行、1000 附件/256 MB，清单 10 MB。账本不包含工具付款关系，工具不包含原账目/原记录/原计划与计算历史；应分别备份相关领域，恢复后核对关联。ZIP 未加密，金额隐藏不改变备份真实金额，私密序列号与凭证也可能包含在内。

应先恢复记录，再恢复计划和账本，最后恢复工具；工具恢复时缺失的账目关联不会在后续自动补绑。当前没有整库覆盖恢复或跨包全模型自动合并；数据库事务不等于多文件跨进程原子切换。文件校验/提交失败会清理本轮新增文件；发布文件中途强杀仍可能留孤立文件，遇到同名残留安全停止，不覆盖本机原件。

## 计划备份与升级

头像设置 → 备份计划与附件 / 恢复计划备份。格式 daily-life-plans / version=1 / schema=2（计划领域格式保持兼容）；包含计划模型、草稿、回收站、规则/例外/日志、标签与附件原件；不含记录正文、系统提醒历史和外观设置。先备份记录，再备份计划，能保留两类内容；本次没有提供整库覆盖恢复。

上限 5000 主项（含分组和草稿）、50000 明细、1000 份附件、256 MB 原件，清单 10 MB。先校验版本、固定表/字段、标识、关系、路径、解压容量、文件清单和 SHA-256，再预览、事务内追加。已有主项编号及其明细保留本机版本；同名分组/标签映射，原件编号冲突拒绝。来源记录不在本包且本机也不存在时解除关联；活动专注变为待核对，本机已有活动计时时拒绝叠加。

恢复前后不替换当前数据库；失败回滚新增数据库内容并清理本轮发布的文件。数据库与文件不具备跨进程原子切换：发布文件时强杀可能留下未登记原件，遇到同名残留会停止恢复，待存储维护处理。ZIP 未加密，勿随意公开。

Room schema 经 1→2→3 加法迁移；保留原版本 schema，不启用清库重建。旧库内部副本是本机应急材料，不能替代用户主动导出的备份。[Room 迁移说明](https://developer.android.com/training/data-storage/room/migrating-db-versions)

## 记录备份

入口：头像设置 → 备份记录与附件 / 恢复记录备份。

ZIP 格式 daily-life-records / version=1，包含正式记录、回收站、资料夹、标签、类型、模板、附件和关联，保留实体 UUID；不含草稿、外观设置或未开发模块。ZIP 未加密，包含信息卡私密字段，导出前展示范围。

轻量备份上限：2000 条记录、1000 份附件、附件总计 256 MB、清单 5 MB。恢复会校验格式版本、UUID、路径、解压大小、文件清单及 SHA-256，先预览再迁入当前本地资料。已有同编号记录保留本机版本；有效日记日期冲突跳过；同名分类映射，同名但结构不同的类型中止。既有记录不覆盖。

恢复使用数据库事务和新增文件失败清理；不替换数据库，不宣称数据库与文件具备跨进程中断的原子切换。进程在文件发布中被强杀可能留下未登记文件，当前会安全拒绝同名残留，需后续存储维护完善。完整覆盖恢复、冲突逐项合并、备份任务日志、加密、全模型备份仍属于 DEV-010/026。

## 工程与依赖

一个 app 模块，各领域使用 ViewModel → Repository → Room / AttachmentStore，页面不直接访问 DAO。Application 持有数据库、仓库和 DataStore 单实例；领域共用写入锁、标签和附件引用。业务无服务器，无网络权限，无广泛存储权限。文件通过系统选择器和 FileProvider 交换。

## 开发与验证

在 Android Studio 打开本目录，Gradle JDK 选择本机 E:/Android/jbr；local.properties 仅记录本机 SDK，不能当共享配置提交。命令行 PowerShell：

    $env:JAVA_HOME='E:\Android\jbr'
    $env:ANDROID_HOME='E:\AndroidSDK'
    .\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
    $env:ANDROID_SERIAL='emulator-5580'
    .\gradlew.bat :app:connectedDebugAndroidTest

16 GB 主机建议先构建，再启动模拟器测试，避免多个空闲编译守护进程同时占内存。资源紧张时可用：

    .\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest --no-daemon '-Pkotlin.compiler.execution.strategy=in-process'

安装包：app/build/outputs/apk/debug/app-debug.apk。测试报告位于 app/build/reports/tests/testDebugUnitTest、app/build/reports/androidTests/connected/debug，静态报告 app/build/reports/lint-results-debug.html。测试专用数据由测试自身创建并清理；不会通过清空业务库来“修复”失败。

本轮实际结果统一见 [任务与交接](../docs/ai/开发任务与交接.md)。模拟器测试不替代 OPPO Find X9 Pro 的系统/输入法/帧率/文件选择器验证。
